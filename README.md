# Z6xToolBox

极米 Z6X Pro 投影仪的折腾工具箱：一个桌面程序，把「怎么接管这台投影仪」的全部经验、命令和实测结果整理在一起，并能直接连上投影仪做检查。

- 每条命令都标明**在哪里执行**（Deck 终端 / ADB / SSH / 电视界面）和**风险等级**（只读 / 可撤销的修改 / 难以撤销），一键复制。
- 命令的输出都是在真机上跑出来的，并写明日期，没有编造的「预期输出」。
- 网上流传或旧记录里的说法，逐条在真机上核对，标成 ✓ 成立、? 未验证、✗ 不成立，并写出实测结果。
- 能通过局域网 ADB 直接读取投影仪信息，做一键体检。

## 内容

| 专区 | 内容 |
|---|---|
| 📖 折腾记录 | 从拿到投影仪到接管系统的经过：U 盘装 App、SSH、强开网络 ADB、精简系统、换桌面、开发环境、应急恢复 |
| 🔍 学会查设备 | 用 adb 查硬件、系统和权限的真实案例；命令手册（含原理）；「换方案记录」：一条路不通时怎么换 |
| 💡 提案 | 还没做的方案和可行性审核；z6x-hub（Go 常驻服务）和 z6x-tools（Rust 命令集）的规格 |
| 🛠 本项目技术栈 | 这个工具箱本身用的 JDK、Gradle、Kotlin、Compose、Git：怎么装、怎么读代码、常见问题 |

## 运行环境

- Linux 桌面（在 Steam Deck 桌面模式上开发和测试）。Windows / macOS 版以后由 GitHub Actions 构建。
- **JDK 21**，放在 `~/Applications/jdk`（不需要 root，不改系统分区）。安装步骤在程序里「本项目技术栈 → 在 Deck 上安装 JDK」。
- 连接投影仪需要：投影仪和电脑在同一局域网、投影仪的网络 ADB（5555 端口）已打开。怎么打开见「折腾记录」。
- 第一次连接前，在终端执行一次 `adb connect 投影仪IP:5555`。工具箱复用 adb 生成的密钥 `~/.android/adbkey`，本身不需要 adb 命令。

## 使用

```bash
./run.sh                 # 打开工具箱
./run.sh --health        # 不开窗口，命令行体检（有必检项异常时退出码为 1）
./run.sh --probe         # 不开窗口，打印设备基本信息
```

默认连接 `192.168.0.109:5555`。地址不同的话，在窗口的「📡 设备」页改，或在命令后面加上地址：`./run.sh --health 192.168.1.20:5555`。

第一次运行会下载 Gradle 和依赖，需要几分钟；之后只编译改动的部分。

窗口里：

- 左侧选专区和分类，`Ctrl+F` 搜索模块或命令。
- 每条命令右侧可以复制；颜色表示风险等级。**高危**命令执行前务必读完说明。
- 「📡 设备」页：读取设备信息、一键体检，异常项可以点「查看」跳到相关说明。

## 出问题时

| 现象 | 去看 |
|---|---|
| ADB 连不上 | 「折腾记录 → 应急与安全」；先确认投影仪不是在「关机」状态（那其实是睡眠，网络是断的） |
| 投影仪重启后自己部署的服务没了 | 正常：没有 root 不能开机自启。ADB 会自动起来，从 Deck 重新启动服务即可 |
| 精简系统后想恢复 | `scripts/z6x_debloat_restore.sh`，说明在「深度定制」 |
| 后台 Java 进程占很多内存 | 「本项目技术栈 → 案例：后台 Java 进程越来越占内存」；`./gradlew --stop` 可以立即释放 |

## 修改内容

内容直接写在 Kotlin 代码里（`composeApp/src/commonMain/kotlin/z6x/content/`），不是 Markdown。改完运行：

```bash
./run.sh --check                 # 静态检查：风险标注、格式、是否泄露敏感信息
./run.sh --try-read [模块id…]     # 在真机上重跑只读命令，和记录的输出对比
```

目录结构和新增一篇内容的步骤见程序里「本项目技术栈 → 这个项目的结构与日常操作」。

## 其他

- `Z6xToolBox.App/`、`Z6xToolBox.Desktop/` 是最初的 Avalonia（C#）版本，保留作对照，不再维护。`./run-avalonia.sh` 可以打开它。
- 不要把代理节点、订阅链接、序列号、MAC 地址等个人信息写进仓库；`--check` 会检查常见的几种。
